# MyCollaboratorBots

여러 AI 봇을 한 팀으로 굴리는 데스크톱 앱(맥·윈도우). 사용자는 **일만 던지고**, **팀장 봇**이 알아서 나눠 맡기고 검토·재지시까지 진행해 최종 결과를 낸다.
사용자는 오른쪽 **진행 상황**에서 과정을 지켜보다가 결과를 **승인**하거나 **수정 요청**만 한다.
[내 문서 검색(MyDocSearch)](https://github.com/koreanregister-ict/DocSearch)의 ‘MyDocBot’을 따로 떼어 낸 앱이다. 내 문서 검색이 설치돼 있으면 봇이 내 PC 문서를 근거로 답한다.

```
나 ─▶ 팀(대화방) ─▶ 팀장 봇: 직접 답하거나 일을 나눔 ─┬▶ 팀원 봇 A ─┐  (동시에, 최대 4개)
                                                  └▶ 팀원 봇 B ─┴▶ 팀장 봇이 모아 최종 답 ─▶ 앱 작업(권한대로)
```

## 기능
- **봇**: 아이콘·이름·역할(지시)·AI(Claude·ChatGPT(Codex)·Gemini)·모델·앱 작업 권한. 처음 열면 ‘예시 팀 만들기’로 팀장·조사·정리·검토 봇과 ‘문서 팀’을 만든다.
- **팀**: 이름·팀장 한 명·팀원 여럿. 같은 봇이 여러 팀에 들어갈 수 있다. 팀에 든 봇은 팀에서 빼야 지운다.
- **일하는 방식 (알아서 진행)**: 팀장은 최근 대화 10개와 요청을 받아, 간단하면 바로 최종 결과를 내고 아니면 답 끝에 ` ```팀작업 [{"봇": "이름", "일": "..."}] ``` ` 블록으로 나눈다.
  팀원들은 동시에 일하고(각자 자기 AI·모델로), 팀장이 결과를 **검토**해 빠졌거나 틀리거나 서로 맞지 않는 부분은 다시 맡긴다 (최대 3차, `MAX_ROUNDS`). 마지막엔 결론 · 근거 · 확인할 점 순서로 최종 결과를 쓴다.
  봇에게는 사용자에게 되묻지 말고 가정을 밝히고 끝까지 하라고 지시한다. 블록은 화면에 보이지 않는다. 팀은 한 번에 한 요청씩 (일하는 중에 보낸 일은 끝난 뒤 이어서).
- **임시 팀원**: 맞는 팀원이 없으면 팀장이 `{"봇": "새 이름", "역할": "...", "일": "..."}`로 이번 일에만 쓰는 팀원을 만든다 (팀장과 같은 AI·모델, 앱 작업 권한은 보기만). 팀원을 정해 두지 않고 팀장만 있어도 된다.
- **판단**: 최종 결과에 ✅ 승인 · ✍️ 수정 요청. 수정 요청은 의견을 붙여 팀에 다시 보내 팀장이 이어서 고친다. 결과가 나오면 운영체제 알림.
- **진행 상황 (오른쪽)**: 가장 최근 일의 상태(진행 중 · 판단 기다림 · 승인함 · 멈춤 · 문제 있음)와 걸린 시간, 단계(계획 → 맡은 일 → n차 검토 → 최종 결과)마다
  맡은 봇 · 맡은 일 · 시간 · 지금 찾는 것(마지막 도구와 검색어) · 부른 도구 수, 허용을 기다리는 앱 작업 수. 항목을 누르면 대화의 그 자리로 간다. 멈추기 · 승인 · 수정 요청 버튼.
- **앱 작업 권한 (봇마다)**: 봇은 답 끝에 ` ```앱작업 [{"도구": "save_document", "인자": {...}}] ``` `로 요청한다.
  쓸 수 있는 작업은 문서 저장·모음 만들기·모음에 담기·루틴 실행·OneDrive로 보내기뿐이다 (지우기·이름 바꾸기·설정은 없음).
  - 보기만(기본): 하지 않고 ‘🔒 권한 없음’ 카드만 남김
  - 물어보고 바꿈: 대화방에 허용/거절 카드 — 예약 작업 중에도 내가 허용할 때까지 기다림
  - 바로 바꿈: 확인 없이 바로 (예약 작업 중에도)
- **문서로 저장**: 봇의 답마다 ‘문서로 저장’ → `문서/MyCollaboratorBots/`에 워드로.
- **예약 작업**: 팀마다 매시간·매일·매주 + 그때 맡길 일. 앱이 켜져 있을 때 돈다. 끝나면 알림.
- **멈추기**: 일하는 중에는 보내기 대신 ‘멈추기’. 앱이 꺼져 끝나지 못한 답은 다음에 켤 때 ‘멈춤’으로 남는다.

## 내 문서 검색(MyDocSearch)과 잇기
이 앱은 문서를 직접 색인하지 않고, 설치된 내 문서 검색을 빌려 쓴다 (`src/docsearch.js`). 따로 설정할 것은 없다 — 내 문서 검색 0.3.15 이상을 한 번 켜 두면 된다.

| 내 문서 검색 | 봇이 할 수 있는 일 |
|---|---|
| 없음 | 일반 지식으로만 답함 (문서 도구·앱 작업 없음) |
| 설치됨 · 꺼짐 | 문서 찾기·읽기로 근거와 함께 답함 |
| 켜짐 | + 근거 링크를 그 뷰어에서 열기, 앱 작업(권한대로) |

- **찾기·읽기**: 내 문서 검색이 앱 데이터 폴더에 남기는 `mcp-launch.json`(문서 검색 MCP 서버를 띄우는 방법)으로 봇마다 `MDS_TOOLS=basic`(검색·읽기만) 서버를 붙인다.
- **앱 작업·문서 열기**: 켜져 있는 내 문서 검색의 창구(`control.json` — 127.0.0.1, 비밀 열쇠)로 보낸다.
  조작은 내 문서 검색 → 설정 → AI·보안의 **‘외부 AI가 앱을 조작하도록 허용’**이 켜져 있어야 받는다. 이 앱의 봇 권한과 **둘 다** 필요하다. 한 일은 내 문서 검색의 AI 전송 내역에 `MyCollaboratorBots · 봇이름 · 조작`으로 남는다.
- 근거 링크 `[파일명 · 3쪽](doc:문서ID#c조각ID)`를 누르면 내 문서 검색 창이 앞으로 오고 그 위치가 열린다.

## AI 연결 (설정 → AI 연결)
봇은 이 PC에 로그인한 공식 프로그램으로 일한다. 이 앱은 비밀번호·토큰을 읽거나 저장하지 않는다 (`src/ai.js`, `src/agy.js` — 내 문서 검색과 같은 코드).
- Claude — Claude Code (없으면 공식 설치 스크립트로 설치 → `claude auth login`, 브라우저에 나온 코드를 붙여 넣음)
- ChatGPT — Codex (없으면 공식 배포 파일을 앱 데이터 폴더에 받음 → `codex login`)
- Gemini — Google Antigravity CLI(agy) (공식 배포 목록에서 받아 SHA-512 확인 → 브라우저에서 허용)
- 봇 실행은 AI 자체 도구(파일·명령·웹)를 모두 끄고 내 문서 도구만 허용한다 (Gemini는 도구 문지기 `src/agy-hook.js`).
- ‘연결 끊기’는 이 앱에서만 쓰지 않게 한다 (다른 프로그램과 함께 쓰는 로그인은 그대로). 끊은 AI를 쓰는 봇은 일하지 않고 그 이유를 남긴다.

## 앱 관리
- **버전**: `package.json`의 `version` 하나가 기준이다 (`src/version.js`). 화면 위·설정 → 정보에 보인다.
- **새 버전 알림**: 켤 때와 12시간마다 `github.com/JinyoungPark/MyCollaboratorBots/releases/latest`가 넘겨 주는 주소에서 최신 번호만 읽는다 (보내는 정보 없음, API 한도 없음, 회사 프록시·인증서 그대로). ‘나중에’는 그 버전만 다시 띄우지 않는다.
- **자동 업데이트 (윈도우 zip판)**: ‘지금 업데이트’ → 새 zip을 앱 데이터 폴더/update에 받아 풀고 버전 확인 → ‘다시 시작해 업데이트’ → 받아 둔 새 버전이 지금 앱이 닫히기를 기다렸다 앱 폴더의 파일을 바꿔 끼우고 다시 연다.
  이전 파일은 `_previous`에 두었다가 다음에 켤 때 지운다. 막히면 이전 파일로 되돌리고 직접 받기 안내 (`src/updater.js`). 맥·설치판(setup.exe)은 ‘받기’로 릴리스 페이지를 연다.
- **데이터 형식**: 앱 데이터의 `bots.db`(SQLite)에 `PRAGMA user_version`으로 형식 버전을 남기고, 켤 때 `src/store.js`의 `MIGRATIONS`를 차례로 적용한다. 더 새 버전의 데이터면 열지 않고 업데이트를 안내한다.
- **문제가 생겼을 때**: 설정 → 정보 → ‘진단 정보 복사’(버전·봇 수·최근 오류, 대화 내용 없음) · ‘문제 기록 폴더 열기’(`logs/app.log`, 1MB씩 돌려 씀).
- 앱 데이터 폴더: 맥 `~/Library/Application Support/MyCollaboratorBots`, 윈도우 `%APPDATA%\MyCollaboratorBots`.

## 개발
```bash
npm install
npm start               # 앱 실행
npm run test:unit       # 화면 없는 시험 (버전·일정·데이터 형식·내 문서 검색 잇기·봇 팀 흐름)
npm test                # 앱을 띄워 화면으로 봇 팀 시험 (가짜 AI·가짜 내 문서 검색)
npm run dist:mac        # 맥 dmg (arm64·x64)
npm run dist:win        # 윈도우 setup.exe + portable zip
```

## 배포 (새 버전 내기)
1. `CHANGELOG.md`의 `## 다음 버전` 아래에 바뀐 점을 적는다.
2. `npm run version:patch` (또는 `version:minor`·`version:major`) — `package.json` 버전을 올리고 `## 다음 버전`을 `## x.y.z (날짜)`로 바꾼다.
3. `git commit -am "x.y.z" && git tag vx.y.z && git push --follow-tags`
4. GitHub Actions(`.github/workflows/build.yml`)가 시험 → 맥·윈도우 빌드 → 태그 이름으로 릴리스를 만들고 파일(dmg·setup.exe·portable zip)을 올린다.
   태그와 `package.json` 버전이 다르면 릴리스를 만들지 않는다. 릴리스가 올라가면 쓰는 사람의 앱에 새 버전 알림이 뜬다.
